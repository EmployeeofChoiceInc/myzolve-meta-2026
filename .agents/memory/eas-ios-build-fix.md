## The EAS problem
Replit's sandbox blocks all destructive git operations, so EAS cannot use git-based archival. With `EAS_NO_VCS=1 EAS_PROJECT_ROOT=.../myzolve-connect-mobile`, EAS archives only the mobile directory (~928 KB). Without `pnpm-workspace.yaml` and `pnpm-lock.yaml` in that archive, EAS defaults to yarn — which fails on `catalog:` protocol packages.

## The EAS fix (already applied)
A self-contained mini pnpm workspace lives inside `artifacts/myzolve-connect-mobile/`:

- `vendor/api-client-react/` — copy of `lib/api-client-react` source (no node_modules)
- `vendor/tutorial-content/` — copy of `lib/tutorial-content` source (no node_modules)
- `pnpm-workspace.yaml` — declares `packages: [., vendor/api-client-react, vendor/tutorial-content]` plus `catalog:` entries resolving the four `catalog:` deps in package.json
- `pnpm-lock.yaml` — generated by running `pnpm install --no-frozen-lockfile` in the mobile dir

EAS detects `pnpm-workspace.yaml` → uses pnpm → `Scope: all 3 workspace projects` → installs 1143 packages → build succeeds.

## Side-effect on Replit deployment builds (also fixed)
The local `pnpm-workspace.yaml` caused two cascading failures in the Replit deployment build:

### 1. `scripts/build.js` — wrong workspaceRoot
`findWorkspaceRoot(projectRoot)` walks up looking for `pnpm-workspace.yaml`. It now stops at the mobile dir instead of the repo root. This changes the Metro bundle URL from:
- Correct: `http://localhost:8081/artifacts/myzolve-connect-mobile/node_modules/expo-router/entry.bundle`
- Broken: `http://localhost:8081/node_modules/expo-router/entry.bundle`

**Fix:** Start the search from `path.dirname(projectRoot)` so the mobile-local file is skipped:
```javascript
const workspaceRoot = findWorkspaceRoot(path.dirname(projectRoot));
```

### 2. `metro.config.js` — wrong watchFolders
Expo's `getDefaultConfig` also searches for `pnpm-workspace.yaml` to detect the workspace root for `watchFolders`. It now finds the mobile dir, so Metro only watches the mobile directory. Metro uses the outermost watched folder as the base for bundle URL paths — with only the mobile dir watched, the URL becomes `/node_modules/expo-router/entry.bundle` (not found).

**Fix:** Explicitly add the repo root to watchFolders:
```javascript
const workspaceRoot = path.resolve(__dirname, "..", "..");
const config = getDefaultConfig(__dirname);
if (!new Set(config.watchFolders || []).has(workspaceRoot)) {
  config.watchFolders = [workspaceRoot, ...(config.watchFolders || [])];
}
```

**Why both fixes are needed:** build.js computes the URL; metro.config.js controls which URL Metro can serve. They must agree on the workspace root.

## How to apply after changes to lib packages
If `lib/api-client-react` or `lib/tutorial-content` change, refresh the vendor copies:
```bash
rm -rf artifacts/myzolve-connect-mobile/vendor
cp -r lib/api-client-react artifacts/myzolve-connect-mobile/vendor/api-client-react
cp -r lib/tutorial-content artifacts/myzolve-connect-mobile/vendor/tutorial-content
rm -rf artifacts/myzolve-connect-mobile/vendor/*/node_modules
cd artifacts/myzolve-connect-mobile && pnpm install --no-frozen-lockfile
```

## EAS Build + submit commands
```bash
# Build
cd artifacts/myzolve-connect-mobile && EAS_NO_VCS=1 EAS_PROJECT_ROOT=/home/runner/workspace/artifacts/myzolve-connect-mobile EXPO_TOKEN=$EXPO_TOKEN npx eas-cli@18.8.1 build --platform ios --profile production --non-interactive

# Submit (run after build finishes — command will time out locally but submission IS queued)
cd artifacts/myzolve-connect-mobile && EAS_NO_VCS=1 EAS_PROJECT_ROOT=/home/runner/workspace/artifacts/myzolve-connect-mobile EXPO_TOKEN=$EXPO_TOKEN ./node_modules/.bin/eas submit --platform ios --latest --non-interactive
```

**Why:** Both commands time out locally (npx download / submission wait) but the job IS queued on EAS servers. Check status via GraphQL or the Expo dashboard.
